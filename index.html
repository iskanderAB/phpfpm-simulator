Experiments to try

1. Set visitors to 15, then drop to 2: PHP-FPM kills one idle worker per second until idle is at or below max_spare_servers.

2. Set min_spare_servers to 6 and visitors to 0: PHP-FPM keeps 6 workers ready.

3. Set the leak to 2 MB and max_requests to off: RAM keeps growing. Then set max_requests to 20: workers restart and RAM goes down.

4. Press "Traffic spike": when all workers are busy, the queue grows and the max_children warning appears.

5. Set min_spare_servers above max_spare_servers: you see the error that real PHP-FPM gives.


Simplified model: max_requests is small here so restarts are easy to see (use 500 to 1000 in real life). Real PHP-FPM starts workers in a growing burst (1, 2, 4… up to 32 per second), and real workers handle many requests per second.
